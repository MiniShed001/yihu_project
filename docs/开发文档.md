> 版本:1.0 · 更新:2026-10-19
> 技术栈:Django + SQLite(纯内置组件,无第三方依赖)

---

## 1. 项目概述

本系统是一个基于 Django 的小型医院业务演示系统,覆盖**科室、医生、患者、挂号、就诊记录**
五大业务模块,内置可直接运行的演示测试数据(`seed_data` 命令)。定位是演示/教学用途,
不含登录权限、收费结算、药品库存等生产级功能,数据均为虚构,无真实患者信息。

核心业务闭环:

```
建档患者 → 挂号(选科室+医生)→ 就诊 → 建病历(自动把挂号置为「已就诊」)
                     │
                     └── 可「取消」挂号(不产生病历)
```

与气象系统(项目 `mysite`,端口 8000)共用同一个虚拟环境 `venv`,本系统单独使用
**8001 端口**,二者可并行运行。

## 4. 数据模型(models.py)

实体关系:

```
Department(科室) 1 ── * Doctor(医生)
Patient(患者)    1 ── * Registration(挂号)
Doctor           1 ── * Registration
Registration     1 ── 1 MedicalRecord(就诊记录/病历)
```

### 4.1 Department —— 科室

| 字段 | 类型 | 说明 |
|------|------|------|
| name | CharField(50, unique) | 科室名称 |
| description | CharField(200, blank) | 简介 |

### 4.2 Doctor —— 医生

| 字段 | 类型 | 说明 |
|------|------|------|
| name | CharField(30) | 姓名 |
| title | CharField(20, choices) | 职称:主任/副主任/主治/住院医师 |
| department | ForeignKey(Department) | 所属科室,related_name=`doctors` |
| specialty | CharField(100, blank) | 专长 |
| is_active | BooleanField | 在岗状态(默认 True) |

### 4.3 Patient —— 患者

| 字段 | 类型 | 说明 |
|------|------|------|
| name | CharField(30) | 姓名 |
| gender | CharField(4, choices) | 性别:男/女 |
| birth_date | DateField(null) | 出生日期 |
| phone | CharField(20, blank) | 联系电话 |
| address | CharField(200, blank) | 住址 |
| created_at | DateTimeField | 建档时间(auto_now_add) |

`age` 为 `@property`,按出生日期实时计算周岁;未填出生日期返回 `None`。

### 4.4 Registration —— 挂号/预约

| 字段 | 类型 | 说明 |
|------|------|------|
| patient | ForeignKey(Patient) | 患者 |
| department | ForeignKey(Department) | 科室 |
| doctor | ForeignKey(Doctor) | 医生 |
| visit_date | DateField | 就诊日期(默认当天) |
| status | CharField(10, choices) | `waiting` 待就诊 / `done` 已就诊 / `cancelled` 已取消 |
| fee | DecimalField(8,2) | 挂号费(默认 10.00) |
| created_at | DateTimeField | 挂号时间(auto_now_add) |

### 4.5 MedicalRecord —— 就诊记录/病历

| 字段 | 类型 | 说明 |
|------|------|------|
| registration | OneToOneField(Registration) | 对应挂号,related_name=`record` |
| chief_complaint | CharField(200, blank) | 主诉 |
| diagnosis | CharField(200, blank) | 诊断 |
| prescription | TextField(blank) | 处方/医嘱 |
| note | TextField(blank) | 备注 |
| created_at | DateTimeField | 记录时间(auto_now_add) |

> 所有表 `verbose_name` 均为中文,后台管理自动使用中文界面。
> 外键 `on_delete` 均为 `CASCADE`:删除科室会级联删除其医生;删除患者会级联删除其挂号。

## 5. 表单(forms.py)

全部为 `ModelForm`,字段与模型一一对应:

| 表单 | 绑定模型 | 字段 | 特殊处理 |
|------|------|------|------|
| DepartmentForm | Department | name, description | — |
| DoctorForm | Doctor | name, title, department, specialty, is_active | — |
| PatientForm | Patient | name, gender, birth_date, phone, address | birth_date 用 `<input type="date">` |
| RegistrationForm | Registration | patient, department, doctor, visit_date, fee | 医生下拉框只列在岗医生,并显示「姓名(科室·职称)」 |
| MedicalRecordForm | MedicalRecord | registration, chief_complaint, diagnosis, prescription, note | 挂号下拉框只列「尚未建病历且未取消」的挂号 |

关键点:

- `RegistrationForm.__init__` 通过 `label_from_instance` 自定义医生下拉框显示文案。
- `MedicalRecordForm.__init__` 用 `filter(record__isnull=True).exclude(status='cancelled')`
  过滤可选的挂号,从源头避免一个挂号建两份病历。

## 6. Web 视图与路由(views.py / urls.py)

`app_name = 'hospital'`,根路由在 `hospital_sys/urls.py` 中以 `path('', include('hospital.urls'))`
挂载。全部为**函数视图**,通用模式:`form = XxxForm(request.POST or None)` → 校验通过则
`form.save()` → `messages.success()` → `redirect()`。

| 路径 | 视图 | 方法 | 说明 |
|------|------|------|------|
| `/` | index | GET | 总览仪表盘:各计数 + 最近 8 条挂号 |
| `/departments/` | departments | GET/POST | 科室列表 + 新增 |
| `/doctors/` | doctors | GET/POST | 医生列表 + 新增 |
| `/patients/` | patients | GET/POST | 患者列表 + 建档 |
| `/registrations/` | registrations | GET/POST | 挂号列表 + 新增 |
| `/registrations/<pk>/action/` | registration_action | POST | 挂号状态流转(完成/取消) |
| `/records/` | records | GET/POST | 就诊记录列表 + 新增 |
| `/admin/` | Django admin | — | 后台管理 |

### 6.1 index —— 总览仪表盘

返回 `n_departments`、`n_doctors`(仅统计在岗)、`n_patients`、`n_registrations`、
`n_today`(visit_date = 今天)、`n_waiting`、`n_done`、`n_records` 八项计数,
以及 `recent_regs`(按 `created_at` 倒序取前 8 条,`select_related` 预取)。

### 6.2 registration_action —— 挂号状态流转

只接受 POST,读取 `request.POST['action']`:

- `done` → 状态置 `done`(已就诊)
- `cancel` → 状态置 `cancelled`(已取消)

> 注意:这里「完成」只改状态,不会自动建病历;建病历的唯一入口是「就诊记录」页,
> 建病历时才自动把对应挂号置为 `done`(见 records 视图)。

### 6.3 records —— 建病历联动

`form.save()` 拿到新病历后,取出 `rec.registration`,将其 `status` 置为 `done`
并 `save(update_fields=['status'])`,实现「建病历 = 就诊完成」的业务一致性。

## 7. 模板与样式

- `templates/hospital/base.html`:公共布局(header / nav / messages / footer)+ 内联 CSS。
  绿色主题(`#0e7c66`),响应式网格。导航高亮通过
  `request.resolver_match.url_name` 判断。
- 六个页面均 `{% extends 'hospital/base.html' %}` 覆盖 `content` 块。
- 列表页统一采用 `.two-col` 双栏布局:左侧列表 + 右侧新增表单。
- 状态标签 `.tag` 三色:待就诊(橙)/ 已就诊(绿)/ 已取消(红)。
- 全局 `{% if messages %}` 块在 base 中统一渲染 Django 的 flash 消息。

## 8. 管理命令

### 8.1 `seed_data` —— 写入演示测试数据

```
../venv/bin/python manage.py seed_data
```

可重复执行:先按「子表 → 父表」顺序清空(MedicalRecord → Registration → Doctor →
Patient → Department),再重建,保证数据确定。写入内容:

| 数据 | 数量 | 说明 |
|------|------|------|
| 科室 | 8 | 内科/外科/儿科/妇产科/骨科/眼科/口腔科/皮肤科 |
| 医生 | 10 | 四种职称分布 |
| 患者 | 10 | 含年龄跨度(1954–2018 年出生) |
| 挂号 | 12 | 含待就诊/已就诊/已取消三种状态 |
| 就诊记录 | 8 | 主诉/诊断/处方齐全 |

挂号记录通过「患者索引、科室名、医生名、距今天数、状态、挂号费」六元组定义,
日期基于 `timezone.localdate()` 相对推算(如 0 = 今天、4 = 4 天前)。

## 9. 安装与运行

```bash
cd /home/lihui/django_workspace/hospital_sys

# 首次:创建数据库表
../venv/bin/python manage.py migrate

# 写入演示测试数据(可重复执行)

# 启动开发服务器(本机 8001 端口,避免与气象项目 8000 冲突)
```

```bash
nohup ../venv/bin/python manage.py runserver 0.0.0.0:8001 > server.log 2>&1 &
```

## 11. 扩展指南

### 11.1 新增业务字段

1. 在 `hospital/models.py` 对应模型加字段;
2. `../venv/bin/python manage.py makemigrations hospital` 生成迁移;
3. `../venv/bin/python manage.py migrate` 应用;
4. 如需在页面上编辑,同步更新 `forms.py` 的 `fields` 与对应模板表格列。

### 11.2 增加登录权限

当前所有页面匿名可访问。可复用 Django 自带 `auth`,在视图加
`@login_required` 装饰器,或引入 `LoginRequiredMixin`(若改为类视图)。

### 11.3 挂号-医生联动(级联下拉)

目前「新增挂号」表单里科室、医生是两个独立下拉框。若要实现「选科室后医生联动」,
需在模板引入少量 JS(监听科室 change 事件,异步/预置映射过滤医生选项),或将表单
改为前端动态渲染。

### 11.4 修改端口

`runserver` 端口在启动命令里指定;如遇 8001 被占用,改为其他端口即可(如 8002),
README 与本文档同步更新。

## 12. 已知问题与注意

1. **无登录与权限控制**:任何能访问端口的人都能增删改数据,仅适合本地演示/教学。
2. **建病历与「完成挂号」两条路径并存**:挂号页的「完成」按钮只改状态不建病历,
   与「就诊记录」页建病历自动置 done 的业务逻辑存在潜在不一致,使用时需注意口径。
3. **删除级联**:删除科室/患者会级联删除关联数据(CASCADE),后台操作需谨慎。
4. **`seed_data` 为覆盖式**:每次执行会清空全部业务数据重建,不要在生产数据上运行。
5. **年龄实时计算**:`Patient.age` 依出生日期动态计算,未填出生日期显示「—」。
